# bmo-gate

턴의 게이트 단계를 독립된 하나의 서비스로 만든 것입니다. 채팅 수신기가 턴의 봉투를 만든 시점부터 에이전트의 답변이
방으로 돌아가는 시점 사이에서 게이트는 다음 일을 합니다.

- **턴에 참조 자료를 넘깁니다.** 고르지 않고 그대로 넘기며, 화자별 시트 머리, 방의 기한이 된 기억, 턴의 이벤트가 깨우는
  행이 여기에 해당합니다. 또한 브레인의 색인과 그 조각, 색인 검색을 제공하며, 에이전트는 이를 통해 브레인의 나머지를
  읽습니다.
- **번역합니다.** 작업자나 문서가 다른 언어로 필요로 하는 내용을 번역하고, 그 번역을 보관합니다.
- **기록합니다.** 전달받은 모든 판단과, 각 실행이 거친 경로를 기록합니다.

게이트 순서에는 게이트가 하나도 없습니다. 에이전트가 자기 답변의 형식을 직접 정하고 자기 세션을 직접 유지합니다
(`docs/gates.md`). 턴이 사용할 수 있는 대형 텍스트 모델은 여기에 없습니다. 그 모델은 별도의 OpenAI 호환 엔드포인트로
존재하며, 게이트는 등록 정보로만 그것에 접근합니다.

다른 모든 유닛에는 표준 API로만 접근하며, 다른 저장소 중에서는 기반 라이브러리인 `bmo-chat`, `bmo-chat-client`,
`bmo-ui`에만 의존할 수 있습니다.

## 폴더

| 폴더 | 내용 |
|---|---|
| `crates/` | 루트 패키지를 구성하는 Rust 크레이트: 계약과 클라이언트, 저장소, 코드, 다른 유닛으로의 포트, 정책, 단어, 마크업, 실행, 번역 단계, 참조 경로, 서비스 라우트, 유닛 명령 |
| `deploy/` | 테스트베드의 배포가 운영 머신에 유지하는 서비스 유닛 `bmo-gate-server.service`와, 배포가 중지·비활성화·링크 해제하는 `retire` 표시 유닛 |
| `docs/` | 코드보다 먼저 오는 문서. `docs/layout.md`부터 읽고, 공개 API는 `docs/api.md`, 그 기계용 형식은 `docs/openapi.json`을 보십시오 |
| `package/` | `docs/openapi.json`에서 생성한 TypeScript 클라이언트 |
| `runtime/` | GGUF 엔진의 유닛 템플릿과 노드 설정(`docs/gguf-llm.md`) |
| `src/` | 루트 패키지: 버전, `gate-server` 바이너리, `bmo-gate` 유닛 명령 |
| `tests/` | 저장소의 모든 테스트 |
| `tools/` | 도구 호스트가 배치하는 도구: 번역기 도구 `gate/translate`, 그리고 브레인 색인 도구 `gate/reference_index`, `gate/reference_piece`, `gate/reference_search`. 각각 매니페스트, 스키마, 매뉴얼, 실행 파일을 갖습니다 |
| `training/` | 배포가 운영 머신에서 실행하는 도구 모음: 독립된 Bun 프로젝트로, GGUF 모델을 노드에 배치합니다(`docs/gguf-llm.md`) |

`PERSONAL-DATA.md`는 어떤 파일에도 담아서는 안 되는 개인 정보를 정합니다. 누구의 정보인지, 무엇이 해당하는지, 값이
대신 있어야 할 곳, 그리고 이를 지키는 검사가 적혀 있습니다.

## 변경 검사

- `cargo check --workspace --all-targets`: 정적 검사.
- `cargo fmt --all --check`와 `cargo clippy --workspace --all-targets -- -D warnings`: 리뷰.
- `cargo test`: 저장소 검사를 포함한 모든 테스트. 개인 정보 검사는 선언에서 활성화된 테스트베드의 빠른 검사입니다.

## 버전

버전은 `VERSION`과 워크스페이스 매니페스트에 같은 번호로 적혀 있습니다. bmo-chat의 `docs/conventions.md` 「Versions」에
적힌 대로 소유자가 선언한 릴리스에서만 바뀌며, 커밋, 배포, 수정, 계약 변경으로는 바뀌지 않습니다. 배포는 커밋으로
구별합니다.
