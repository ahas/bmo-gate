# bmo-gate

ターンのゲート段階を、独立した 1 つのサービスにしたものです。チャットレシーバーがターンのエンベロープを組み立ててから、
エージェントの回答がルームに戻るまでの間に、ゲートは次のことを行います。

- **ターンに参照資料を渡します。** 取捨選択はせず、話者ごとのシートの冒頭、ルームの期日が来た記憶、ターンのイベントが
  呼び起こす行を渡します。また、ブレインのインデックスとその断片、インデックスの検索を提供し、エージェントはそれを通じて
  ブレインの残りを読みます。
- **翻訳します。** ワーカーやドキュメントが別の言語で必要とするものを翻訳し、その翻訳を保管します。
- **記録します。** 伝えられたすべての判断と、各実行がたどった経路を記録します。

ゲートの順序にはゲートが 1 つもありません。エージェントは自分の返答の書式を自分で整え、自分のセッションを自分で保持します
(`docs/gates.md`)。ターンが使うことのある大規模テキストモデルはここにはありません。それは独自の OpenAI 互換エンド
ポイントとして存在し、ゲートは登録情報としてのみそこに到達します。

他のすべてのユニットには標準 API だけで到達し、他のリポジトリのうち依存してよいのはベースライブラリの `bmo-chat`、
`bmo-chat-client`、`bmo-ui` だけです。

## フォルダ

| フォルダ | 内容 |
|---|---|
| `crates/` | ルートパッケージを構成する Rust クレート:契約とそのクライアント、ストア、コード、他ユニットへのポート、ポリシー、語、マークアップ、実行、翻訳ステージ、参照の経路、サービスのルート、ユニットコマンド |
| `deploy/` | テストベッドのデプロイが運用マシン上で維持するサービスユニット `bmo-gate-server.service` と、デプロイが停止・無効化・リンク解除する `retire` 指定のユニット |
| `docs/` | コードに先立つドキュメント。まず `docs/layout.md` を読み、公開 API は `docs/api.md`、その機械可読形式は `docs/openapi.json` を参照してください |
| `package/` | `docs/openapi.json` から生成した TypeScript クライアント |
| `runtime/` | GGUF エンジンのユニットテンプレートとノードのセットアップ(`docs/gguf-llm.md`) |
| `src/` | ルートパッケージ:バージョン、`gate-server` バイナリ、`bmo-gate` ユニットコマンド |
| `tests/` | リポジトリのすべてのテスト |
| `tools/` | ツールホストが配置するツール:翻訳ツール `gate/translate` と、ブレインのインデックスツール `gate/reference_index`、`gate/reference_piece`、`gate/reference_search`。それぞれマニフェスト、スキーマ、マニュアル、実行ファイルを持ちます |
| `training/` | デプロイが運用マシン上で実行するツール群:独立した Bun プロジェクトで、GGUF モデルをノードに配置します(`docs/gguf-llm.md`) |

`PERSONAL-DATA.md` は、どのファイルにも含めてはならない個人情報を定めています。誰の情報か、何が該当するか、値が代わりに
置かれるべき場所、そしてそれを守らせるチェックが書かれています。

## 変更のチェック

- `cargo check --workspace --all-targets`:静的チェック。
- `cargo fmt --all --check` と `cargo clippy --workspace --all-targets -- -D warnings`:レビュー。
- `cargo test`:リポジトリのチェックを含むすべてのテスト。個人情報のチェックは、宣言で有効化されたテストベッドのクイック
  チェックです。

## バージョン

バージョンは `VERSION` とワークスペースマニフェストに同じ番号で記されています。bmo-chat の `docs/conventions.md`
「Versions」にあるとおり、オーナーが宣言したリリースでのみ変わり、コミット、デプロイ、修正、契約の変更では変わりません。
デプロイはコミットで区別します。
